- 本地 `npm run check`、`npm run verify:wasm`、全部固定 VICE/reSID/Rust/TypeScript 参考链通过；

- Fedora 45 只有 ICU 78，而 Playwright WebKit 固定要求 ICU 74/libjpeg 8，因此本机未运行 WebKit；
  提交 `fe5d56e` 的远端
  [CI run 31539712745](https://github.com/JamesLinYJ/rust-c64-emulator/actions/runs/31539712745)

### 2026年08月12日 M2 Turbo 语义第一阶段增补（本地候选）

- 2..64 内部 CPU 槽位、一次性 Auto 锁定和 Strict 专用调度路径已经落地；代表全部生产档位的
  10 组 4,096 槽位差分均与 Strict 的 CPU 状态、RAM 写入和总线事务一致。
- `CodePageGuard` 以页能力、页代码 generation 和全局映射 generation 组成复用条件；CPU、REU、
  Enhanced DMA、Host 写入同页都会失效，其他页写入不会误伤页局部 generation。
- Turbo CPU 访问现生成带虚拟时间、主控、读写、物理目标和响应的强顺序 `BusBridge` 事务；
  处理器端口映射切换、REU 即时 DMA 与 `$FF00` 延迟触发均有先失败后修复的根因测试。外设事件
  horizon 保证快速执行不能跨过下一系统周期边界。
- Strict 不生成 Turbo bridge trace，保持原周期精确热路径；本地 Chrome、Edge、Firefox 均恢复
  50 host FPS，当前 Sites 包含 20 个文件、328,945-byte Wasm 且无 source map。本机 WebKit
  仍因 Fedora 缺 ICU74/libjpeg8 不能启动，必须由远端 CI 验收。

## 已完成并有验证证据的实现

### Foundation

- Cargo workspace 已包含 `c64-core` 与 `c64-wasm`。
- 固定 Rust 1.97.0、edition 2024、`wasm32-unknown-unknown`、wasm-pack 0.15.0、wasm-bindgen 0.2.127，并提交 `Cargo.lock`。
- `c64-core` 使用 `#![forbid(unsafe_code)]`；Wasm ABI 为粗粒度接口，不逐周期跨 JS/Wasm。
- 已定义 Strict/Turbo 请求、profile、PAL/NTSC 虚拟时间、统一页能力/版本框架和完整 save-state v2；v1 状态继续兼容。

### Rust Strict 主机核心

- NMOS 6510：全部 256 个合法与非法 opcode、decimal、JAM、IRQ/NMI、RDY、逐周期总线和 6510 处理器端口。
- PLA、统一 64 KiB RAM、ROM/隐藏 RAM、颜色 RAM、Cartridge 地址窗口和页 generation。
- MOS 6526 CIA：计时器、TOD、串口、端口、IRQ/NMI 管线和芯片修订差异。
- VIC-II PAL 6569R3 与 NTSC 6567R8 严格序列：bad line、BA/AEC、fetch、边框、精灵 DMA、碰撞、IRQ、light pen 和逐像素帧缓冲。
- SID：MOS6581/MOS8580 oscillator、combined waveform、noise/test/sync/ring、ADSR、两种滤波器、板级 RC、重采样与有界音频环。
- CIA2 已连接 Rust IEC 开集电极总线，并实现反相的主机输出及 PA6/PA7 输入。

### 1541 Rust 整机

- MOS 6522 VIA Rust 实现已通过 100,015 次 TypeScript 随机差分。
- Rust 与 TypeScript 均逐字节匹配 VICE revision 46176 的 40 个 PB7 页面和 24 个 timer/IFR 页面；参考数据来自真实 1541。
- IEC 总线使用固定容量、generation 校验和无热路径分配的开集电极聚合模型。
- 1541 VIA1 板级接线已实现 DATA/CLOCK 7406 反相、ATNA 门、设备地址位和 ATN→CA1 反相边沿。
- 16 MHz GCR 读写分离电路已实现 UE7/UF4 分频、磁通滤波、同步检测、弱磁通确定序列、写移位和 BYTE READY，并通过 100,008 次 TypeScript/Rust 差分。
- D64 35..42 轨解析、错误字节、写保护、GCR 编解码、标准原始磁道生成和扇区回解码已进入 Rust，并通过 Rust 单元测试。
- VIA2 板级接线、半轨磁盘机构、D64/G64 可写媒体、2 KiB RAM/ROM 地址译码、独立 6502 与整数主机/驱动器时钟已接入 C64Chipset/IEC。
- 完整 VICE revision 46176 `verify:drive` 已通过目录、LOAD、SAVE、format、IEC delay、write-protect、disk-change 与 HLS protection。

### 已完成的 Strict 外设与状态

- Datasette/TAP/Writable TAP 与 6510 motor/write/sense/read 接线已完成并通过 KERNAL LOAD、SAVE/新机 LOAD 和 VICE 波形参考。
- CRT、8K/16K/Ultimax、Ocean、Magic Desk、EasyFlash/AM29F040B 已完成；官方 EasyProg 1.6.3 与 Ocean CRT 参考通过。
- REU copy/fetch/swap/verify、autoload、IRQ、`$FF00` 延迟触发、VIC 优先级和页 generation 已完成；VICE QuickReu 1.1.1 的 8 个功能 PRG 全部通过。
- save-state v2 使用 `RC64VM02`、长度边界、CRC32 与精确解码，覆盖 CPU 微周期、全部芯片、IEC/1541、D64/G64、Tape、Cartridge/EasyFlash、REU/DMA 和确定性继续；v1 可载入，C64 firmware 不嵌入状态。

### 生产 Rust/Wasm Worker

- 生产 React 页面已切换到独立 module Worker 内的 Rust/Wasm Strict 整机；TypeScript 硬件不再是生产 fallback，只保留为差分 oracle。
- firmware 只在初始化时复制进 Wasm；后续按完整帧、PCM 批次、输入快照与 PRG 命令跨越粗粒度 ABI，不逐周期跨 JS/Wasm。
- 键盘矩阵、Shift Lock、双控制口和 RESTORE NMI 已接入 Rust `C64Chipset`；手机现有 `beforeinput` 捕获路径会发送同一输入快照。
- VIC RGBA 帧和 SID PCM 使用固定容量、可回收 Transferable 双缓冲；Worker 从 Rust 整数时钟元数据派生 PAL/NTSC 节拍，主线程只负责 Canvas、Web Audio 与 UI。
- Worker 已提供 run/pause/reset、输入、save/load state、diagnostics、Tape、Cartridge/EasyFlash、REU、1541 attach/detach 及 D64/G64 mount/eject 的版本化粗粒度请求；二进制结果使用精确 Transferable 副本，64 位诊断计数使用 high/low 字段。
- `dist/client` 是经过 Sites 打包并断言无 `.map`/`sourceMappingURL` 的生产产物；CI 将该确切产物传给 Chromium smoke，不再误测缺少 Wasm 的普通 Vite bundle。
- 同一生产产物已在实际 Google Chrome、Microsoft Edge、Playwright Firefox 和 WebKit 中完成 module Worker/Wasm、PAL 帧推进、暂停/单帧/恢复与 BASIC PRG 执行；Node ABI 由同一 `c64-core` 构建。四个浏览器均由远端门禁验收为 50 host FPS。

M4 生产 Worker/Wasm 已由远端四浏览器门禁验收；后续阶段继续把 TypeScript 硬件保留为显式差分
oracle，不恢复生产 fallback。SAB/SIMD 只作 bit-identical 可选路径。

### 1. 完成 Turbo 语义与 uop 引擎

1. 先用简单指令执行器证明 Turbo 虚拟时间、BusBridge、VIC/REU/DMA 所有权和精确退出。
2. 加入预解码、页 guard、热后继、分支目标缓存、安全 fusion、lazy flags、延迟写回和精确 deopt；MMIO 永不推测。
3. 达到 BASIC ≥10×、纯 RAM ≥15×、通用 I/O ≥3× 后再标记 Turbo 稳定。

### 2. 扩展体系结构

1. 实现完整 W65C816/SuperCPU 与 24 位地址/Fast RAM。
2. 最后实现无自定义 opcode 的 VM Enhanced capability、内存池与 Enhanced DMA。

## 不可违反的约束

- 不修改、伪造或批量刷新历史日期；普通修改保留旧日期，新建/实质重构文件使用实际日期和作者。
- Rust、rustc、Clippy、TypeScript、ESLint、Wasm build 不允许任何 warning，也不使用全局 suppression 伪造零警告。
- 不针对软件名称、ROM、磁盘哈希或 benchmark 特判；优化只依据公开地址属性、事件和运行时热度。
- `c64-core` 保持 safe Rust；若 Wasm facade 最终确需 unsafe，必须最小隔离并增加边界测试。
- 固定外部参考版本与 SHA-256；不得用项目自身输出替代 VICE/真实硬件 oracle。
- 每项顺序：根因测试 → 实现 → 本地全门禁 → commit/push → 远端 CI；CI 通过后才关闭对应 issue。
- 未达到相应验收条件时，不宣称完整迁移、完整兼容或稳定。
